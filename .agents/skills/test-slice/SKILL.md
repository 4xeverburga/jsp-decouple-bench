# Test slice — add one behavior case to a sample

A **slice** is a feature boundary (`vote-flow`); a **case** is one
observable behavior of it. One case = one directory, named
`<slice>__<behavior>`, under the sample:

```
src/gates/functional_parity/cases/<sample>/<slice>__<behavior>/
├── case.json      # e2e contract + db contract (hand-written)
├── flow.py        # the Playwright flow — single source of truth (hand-written)
├── expect.json    # frozen golden — GENERATED by `make case-capture`
└── images/        # step screenshots from the golden capture (generated)
```

## Procedure

### 1. Design the behavior (read the sample's source)

Trace the controller/route for the behavior in the sample checkout
(`../<sample>/src`). Note the exact route paths, the widget that triggers
it, permission/karma gates (and whether the seeded actor bypasses them),
and which tables the DAO layer touches. Split multi-behavior ideas into
separate cases — granularity makes verdicts diagnosable.

### 2. Author `case.json`

Copy a sibling case of the same sample and adjust:

```json
{
  "sample": "mamute",
  "case": "vote-flow__upvote-increments-count",
  "e2e": {
    "routes": ["/login", "/question/{id}/voto/positivo"],
    "locale": "en-US", "timezone_id": "UTC",
    "viewport": {"width": 1280, "height": 800},
    "auth": "mixed",
    "credentials": "env:MAMUTE_ADMIN_USER,MAMUTE_ADMIN_PASSWORD",
    "requires_db_reset": true,
    "artifacts": ["vote_count_before", "vote_count_after"]
  },
  "db": {"tables": [{"name": "Vote", "key_columns": ["id"],
                     "ignore_columns": ["createdAt"]}], "notes": ""}
}
```

`locale`, `timezone_id` and `viewport` are the determinism contract —
never omit them, never take them from the host.

### 3. Author `flow.py`

Rules (all hard-won — violating any of these cost a debug cycle):

- **Self-contained arrange**: sign up / create entities in-flow with
  deterministic fixed credentials; act with the seeded actor whose
  credentials come from `os.environ` only (the harness injects the
  sample `.env`). Never hardcode passwords, never rely on prior state.
- **Wait for submit navigations explicitly**:
  `with page.expect_navigation(wait_until="load"): page.click(...)` —
  `click` + `wait_for_load_state` races the redirect.
- **Wait for signals, never sleep**: `page.expect_response("**/route")`
  around the action click; `wait_for_load_state("networkidle")` after
  navigation; `wait_for_function` for DOM updates — and when building a
  JS predicate with `%` formatting, check the braces survive it (a
  missing `}` here once broke every vote wait).
- **Legacy widgets need UI driving**: select2 v3 inputs are hidden —
  click `.select2-container`, `fill(".select2-input", ...)`,
  `wait_for_selector(".select2-result-selectable")`, click the result.
  Filling the hidden input times out.
- **Snapshots**: normalize `page.content()` (strip `<script>/<style>`,
  collapse whitespace) before/after the act; return the artifacts dict
  whose keys are exactly `e2e.artifacts`.

### 4. Author the db contract

Start from a sibling case's table list for the same slice, then let the
capture correct it empirically (it reports every table that changed
outside the spec). Key columns come from `DESCRIBE <table>` — join tables
in mamute use `tags_id`/`watchers_id`, not `Tag_id`/`Watcher_id`. Ignore
every volatile column (all timestamps, counters not asserted on). Exclude
auth plumbing (e.g. `UserSession`) deliberately and say why in `notes`.

### 5. Capture the golden

```bash
# pristine state is mandatory: ids must match across runs
make case-capture SAMPLE=<sample> CASE=<slice>__<behavior> \
                   SAMPLE_LOCATION=../<sample>
```

`case-capture` asserts the checkout is at the pinned commit **and clean**,
resets the stack (`down -v && up --wait`), dumps the case's tables, runs
`flow.py` (screenshotting every `goto`/`click`), dumps again, and writes
`expect.json` = `{db: <before/after delta>, artifacts: {...}}`. Images are
copied into the case directory. **Never hand-edit `expect.json`.**

### 6. Determinism gate (mandatory)

Run `case-capture` a second time; `expect.json` must be identical
(`git diff --exit-code src/gates/functional_parity/cases/<sample>/<case>/`).
Ids are stable because every fresh boot replays the same seed — if they
differ, the environment is not deterministic; stop and fix that first.

### 7. Wire it into a manifest

```bash
# seeds/manifests.json: add the case to the right sample+name entry
make db-init
make manifests          # confirm the case count went up
```

A new *slice* (not just a behavior) also needs its own entry:
`{"sample": ..., "name": "<slice>", "task_type": "decouple_slice",
  "version": 1, "prompt": ..., "bindings": {...}, "scope": {"cases": [...],
  "routes": [...]}}`. `name` is the slice; `task_type` is only the *kind*
of work — identity is `UNIQUE(sample, name, version)`.

## Pitfalls that cost a debug cycle (learned on mamute + openclinica)

- **Pick the behavior direction that leaves a DB fingerprint.** mamute's
  unwatch only deletes a join-table row (the `Watcher` row persists —
  `Question.remove(Watcher)` mutates an in-memory list), so the before/
  after dump nets to zero and there is no signal. Capture the *insert*
  direction instead, and document the quirk in the db contract's `notes`.
- **Forms that prefill volatile values break determinism.** openclinica's
  AddNewSubject prefills `enrollmentDate` with *today* — fill every date
  explicitly with a fixed value before submitting.
- **Legacy apps stall on keep-alive reuse** (openclinica intermittently
  hangs `goto`). Wrap navigation in a goto-with-one-retry helper instead
  of sleeping.
- **A partial flow still writes rows.** A killed capture leaves the DB
  dirty; always reset before the next capture, not just before the first.
- **Never capture against a dirty checkout** — it is refused, and that is
  correct: a golden taken from modified code is not a golden.
